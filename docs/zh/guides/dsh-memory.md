# 与 PowerContext 的 DSH 插件共享记忆

简体中文 · [English](../../en/guides/dsh-memory.md) · [文档首页](../README.md)

不接入 PowerContext，桌宠也能使用。保持默认的「原生近期对话」，配置好聊天模型后，聊天、语音、动画和机器人控制均沿用原有功能。

## 选择记忆模式

| 模式                          | 连接与范围                                               | 桌宠写入什么                           |
| ----------------------------- | -------------------------------------------------------- | -------------------------------------- |
| 原生近期对话（默认）          | 不需要 PowerContext                                      | 本机桌宠对话                           |
| PowerContext                  | 桌宠管理或单独配置的服务，每只桌宠有独立 Scope           | 本机对话，并将完整问答作为 Source 采集 |
| 使用 DSH 的 PowerContext 插件 | 复用运行中的 DSH 插件连接，使用当前 DSH 会话的工作区绑定 | 只保存本机对话，对项目记忆只读         |

共享模式需要本次桌宠版本，以及提供 `powercontextCompanionMemory` 服务、协议为 `powercontext.companion-memory.v1` 的 `powercontext-dsh` 版本。旧插件仍可供 DSH 使用，但不能为桌宠提供这个接口；桌宠会提示更新，并继续普通聊天。勾选共享模式不会自动安装或启用宿主插件。

## 启用项目召回

1. 在 DSH 中安装并启用 PowerContext 插件，通过 PowerContext 侧栏或 `/pc doctor` 检查连接。
2. 打开项目的 DSH 会话。宿主读取该会话的实际工作目录；浏览器只发送会话 ID。
3. 按下方步骤将工作区关联到已有 PowerContext Scope。只用一个项目时，也可以设置 DSH 插件的 `POWERCONTEXT_DSH_SCOPE_ID`。这个显式设置会覆盖该宿主内所有工作区；需要按项目分别绑定时，应移除它。
4. 打开「设置 → 桌宠配置 → AI 模型与对话上下文 → 长期记忆」，选择「使用 DSH 的 PowerContext 插件」，保存。
5. 打开「桌宠对话」，查看项目名、已解析的 Scope 和最近召回结果。询问该范围内已经保存为 Memory 的事实；桌宠按当前问题限量召回，将结果作为历史证据用于回复。

无需再填一份 URL 或 Token。凭据、传输策略和范围解析留在 DSH 插件中。共享模式不会另起 PowerContext 进程，并会禁用单独的本机记忆准备控件。如果原先已有桌宠管理的记忆服务在运行，它会继续运行到暂停或宿主退出，数据库会保留。

### 关联工作区

使用 PowerContext 的 `set_scope_binding` 接口或工具，绑定一个已有 Scope。绑定键为 `integration: dsh`、`kind: workspace`，`external_id` 是宿主中当前会话绝对工作目录的 SHA-256。在 **DSH 所在机器**上打开终端，进入该工作目录后执行：

```sh
node --input-type=module -e 'import {createHash} from "node:crypto"; import {resolve} from "node:path"; console.log(createHash("sha256").update(resolve(process.cwd())).digest("hex"))'
```

向 `PUT /v1/scope-bindings` 提交：

```json
{
  "key": {
    "integration": "dsh",
    "kind": "workspace",
    "external_id": "<上一步输出的哈希>"
  },
  "scope_id": "<已有项目 Scope ID>"
}
```

沿用服务端正常认证方式，密钥不要写进桌宠配置。桌宠不会替你新建 Scope，也不会自动选用服务端默认范围。需要隔离长期记忆时，为不同项目绑定不同 Scope；如果主动绑定到同一个 Scope，它们就会共享该范围的记忆。

## 打通了哪些内容

DSH 插件继续负责原有的对话采集和记忆整理。桌宠读取当前项目的 **Memory**，不会重复采集 DSH 对话，不会将桌宠聊天上传到代码项目的 Scope，不会合并桌宠私有记忆，也不会自动搜索父级、用户或其他项目的范围。这一版不扩展到 Profile 等其他记忆类型。

桌宠近期聊天按连接身份、工作区和 Scope 分开选择。切换项目会显示对应本机历史；切回原生或独立 PowerContext 模式，会恢复该模式的历史。已有记录和私有采集队列保留。「清空全部聊天」仍会清空该桌宠的所有本机分区，不会删除远端项目记忆。项目记忆的管理仍在 PowerContext 中进行，共享模式不显示桌宠私有的「记得的事」编辑入口。

## 共享记忆不可用时

| 提示                   | 处理方式                                             |
| ---------------------- | ---------------------------------------------------- |
| 插件未安装或版本不兼容 | 安装或更新 DSH PowerContext 插件，启用后重新加载宿主 |
| 请打开项目会话         | 在 DSH 主视图中打开一个项目                          |
| 范围不可用             | 检查工作区绑定或显式 Scope 设置                      |
| 连接不可用或超时       | 修复 DSH 插件连接，下一条聊天会重新尝试召回          |
| 没有相关记忆           | 连接正常，本次问题没有找到可用 Memory                |

无法确定项目时，桌宠仍会使用原有人设和当前消息回复，不携带此前的项目聊天历史；降级期间的问答保存在本机。与原生模式一样，聊天模型仍需配置好。独立运行没有 DSH 宿主服务，也会如此降级，建议选择原生或独立 PowerContext 模式。

本功能与 Astra Pro 2.0 的连接独立，不会增加机器人权限或自动触发实体动作。

DSH 内桌宠的 HTTP 读写沿用宿主登录令牌或 Cookie。请通过正常的 DSH 登录链接进入；未登录请求返回 401。独立模式继续使用自身认证，桌面助手继续使用 IPC 连接。
