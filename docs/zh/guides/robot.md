# Astra Pro 2.0 MCP 接入

本分支通过 MCP Streamable HTTP 连接机器人服务，不需要客户端 Python 或 Astra SDK。

1. 构建并启动本分支的桌宠，打开 Astra Pro 2.0 机器人面板。
2. 填入完整地址 `http://<服务IP>:8182/hz-dual-robot-product/mcp`，启用连接，保存配置。
3. 点击“检查连接”，获取示教程序和移动区域目录。连接成功仅表示 MCP 可用，不表示机器人静止。
4. 添加动作，选择“示教程序”或“移动区域”，从目录选择目标，填写名称并保存。示教程序 ID 全程作为字符串保存和传输。
5. 重新检查连接，现场确认设备姿态与周围空间，允许下一次动作，再执行选中的动作。对话动作默认也需要逐次确认。
6. 播报文本通过 `textToSpeech` 执行。可开启“机器人播报桌宠发言”。

默认请求超时 60 秒，可配置为 3–3600 秒。超时或取消不会重试；实体动作可能仍在执行，需现场确认。当前服务没有停止工具，“取消本地等待”不会停止机器人。工具返回成功也不能区分示教程序正常结束与服务端停止信号，请现场核实。

配置迁移：旧版 `astra-robot.json` 中的 Python/gRPC 配置和动作 ID 不可直接复用。升级后保持禁用，重新填写 MCP 地址并从新目录配置动作；已有请求记录保留。

若网关要求鉴权，在启动宿主前设置环境变量 `DSH_PET_ROBOT_MCP_HEADERS` 为 JSON 请求头对象，例如 `{"Authorization":"Bearer <token>"}`。它只从宿主进程环境读取，不进入面板配置或日志。修改后重启宿主。

协议实现采用官方 MCP SDK，执行初始化、分页工具发现、运行时参数 schema 校验及会话释放。执行前重新查询目录，保持程序 ID 或站点字符串原样传递。主机内动作串行执行；多个桌宠宿主或其他控制端仍需要现场协调。

源码地图：

| 文件                           | 职责                         |
| ------------------------------ | ---------------------------- |
| `src/host/robot/mcp.ts`        | MCP 会话、发现与工具调用     |
| `src/host/robot/config.ts`     | MCP 地址及动作配置校验       |
| `src/host/robot/service.ts`    | 逐次授权、串行执行与请求记录 |
| `src/client/robot/settings.ts` | 目录选择及配置面板           |

验证：`npm run test:robot` 使用本地模拟 MCP 服务覆盖 JSON/SSE、会话、长整数、目录失败、工具失败、超时与授权。此验证不能替代现场设备联调。

机器人向桌宠发送语音或文字，请参见 [Astra 语音与桌宠对接说明书](./astra-voice-integration.md)。

## 播报回答与对话推荐动作

在机器人面板的“连接与示教动作 → 对话联动”中开启“允许对话触发已配置的机器人动作”。默认情况下，聊天只生成建议，点击“现场确认并执行此动作”才会执行。

需要免逐次点击时，勾选“直接执行模式（无需逐次确认）”并保存。此开关会同时开启对话动作；保存后立即生效，不需要重启。模型识别到当前用户明确提出的动作请求后，只能选择已配置动作，服务端检查连接并串行下发。若机器人正在播报，会先等待播报结束。界面会标明直接执行模式，模型不会再要求逐次点击确认，也不会宣称实体动作已完成。

直接执行模式默认关闭，旧配置升级不会自动开启。关闭对话动作会同时关闭该模式；关闭直接执行模式并保存后恢复逐次确认。待执行动作不落盘、不在重启后重放；新对话、取消本地等待或修改配置会撤销旧建议，等待超过两分钟不执行，失败或超时不自动重试。仍需保持现场看护；取消本地等待不等于停止设备。

宿主不再每五秒初始化 MCP 查询目录，只在检查连接或实际操作需要时连接。播报回执仅显示在控制面板，避免把成功提示再播放一遍。
