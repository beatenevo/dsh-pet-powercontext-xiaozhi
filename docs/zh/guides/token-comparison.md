# 在 DSH 中对照回答与 Token 用量

[English](../../en/guides/token-comparison.md)

这是开发中功能，需要使用包含对照面板的构建。已发布的 `0.1.0-beta.1` 包不包含此功能。

在 DSH 中打开 **桌宠对话 → Token 对照**。面板沿用 DSH 的主题与当前桌宠头像，在桌面宽屏上保留宿主侧栏和桌宠，并排展示两组独立生成的回答。独立桌宠的聊天窗口也提供相同工具。

## 准备与运行

1. 配置桌宠聊天模型，或选择宿主当前模型。实验固定供应商和模型，各组使用相同的指令、温度及输出限制；调用失败不会切换到其他模型。
2. 在桌宠记忆设置中保存直连 PowerContext Server 配置。即使日常聊天使用原生记忆或 DSH 共享记忆，实验仍使用此连接。伴侣读取服务保持只读，实验不会向现有桌宠或项目记忆范围采集数据。只在 `powercontext-dsh` 中配置的服务地址，不会自动成为桌宠的直连配置。
3. 可选：[连接 AI Vision](observability.md)，并配置 Server 的导出器。不连接也能运行实验，只是没有调用链链接。
4. 粘贴原始背景记录，每行输入一个问题。运行前先确定回答应满足的要求。记录不超过 **49,152 个 UTF-8 字节**，问题最多 **8 个**，短历史预算为 **128 至 8,192 字节**。
5. 点击 **准备记忆并运行**。系统新建独立持久范围，将原始记录作为一个 Source 提交，显式处理一个窗口，并确认已有可用记忆后生成回答。仅接收 Source 不代表记忆已经就绪。此操作会产生模型费用。
6. 点击“回答对照”旁的问题编号切换题目，检查两栏回答，并展开下方的短历史控制组。切题会保留本次的人工检查标签。为回答标注符合要求、缺失或错误、待检查。在再次运行或重启宿主前导出 JSON 结果。

**继续复用本次记忆**可在完成后追加一批问题。每批最多 8 个，累计最多 32 个。保留原始背景、模型、召回配置与范围，不会再次采集或准备记忆，累计输入只计算一次准备账本。允许重复问题，但应注明是复用试验，不能当成新增的独立质量样本。

每次运行的背景资料保持固定，生成的回答不会进入后续提示词或记忆。完整历史组发送全部背景；记忆组发送相同背景的有限 UTF-8 尾部及真实召回内容；控制组只发送同一尾部。不同问题交替运行顺序，以暴露顺序与缓存影响。这是**受控的上下文策略回放**，不是 DSH 任务 Agent 执行，也不是测量 DSH 默认压缩策略。普通 DSH 插件会追加准备好的上下文，仅启用插件不能证明节省 Token。

## 阅读面板

顶部摘要同时展示回答输入减少、含记忆开销的输入减少以及回答与记忆生成的输出合计。展开 **Token 明细与 AI Vision** 可查看各策略合计、准备及累计账本、实验范围和准备阶段调用链。**导出结果**和**关闭**固定在标题栏；按 Escape 也可关闭并返回桌宠对话。

- **回答输入 Token 减少**比较全部已完成配对的供应商输入统计，包含单独报告的缓存桶。回答不完整或输入用量缺失时，不显示汇总减少比例。
- **已报告输入（含记忆，不是金额）**将记忆组回答输入、范围内的生成输入与向量化输入相加。必要的计数或完整回答缺失时保持未知。这是跨模型 Token 计数对照，不是账单；输出另列。减少比例为负数表示输入增加，保留原值，不抹成零。
- 每个回答展示输入、输出、缓存 Token，上下文字节、适用时的召回字节、耗时和可选的 AI Vision 链接。缺失统计保留为未知，只有确实报告零才显示零。人工质量标签是人的判断，不是自动计算的语义等价分数。
- **一次性准备**显示独立范围最初的生成与向量化账本统计。**PowerContext 额外开销**显示最新累计统计，包含准备阶段与后续召回。两者存在包含关系，不要重复相加。
- 账本失败、处理未完成或用量未报告时，不能宣称完整的净节省。记忆生成、向量化和回答可能使用不同模型与分词器，累加 Token 不是金额估算。缓存价格、失败调用、输出与供应商账单需要分别核对；工具不会虚构价格或回本点。

在 AI Vision 中，回答链接指向 `dsh_pet.comparison.answer` 根节点、模型调用以及适用时的召回阶段。准备阶段有独立的 `dsh_pet.comparison.prepare` 调用链。元数据包含随机实验 ID（`dsh_pet.comparison.id`）、策略（`prepare`、`full`、`memory`、`short`）以及从 1 开始的问题编号（`dsh_pet.comparison.round`，准备阶段为 0）。提示词、回答、原始记录和凭据不进入可观测性 span。采集端接收成功之后，仍需查询存储及界面回读才能证明完整观测链路。

## 现场展示前检查

开始对照前，分别验证普通桌宠聊天、记忆生成和召回。Server 健康检查通过后，仍可能存在生成协议不支持、模型不可用或向量化配置错误。聊天供应商与 PowerContext 推理供应商分别配置；地址“兼容 OpenAI”本身不能证明同时支持 Chat Completions 与 Responses。

自定义供应商需要在 DSH 中正确声明模型支持的推理模式和消息角色。只有模型声明支持关闭推理时，对照才会请求关闭。持续推理的模型可能在完成回答前耗尽 1,024 Token 输出预算。修正供应商配置后重新开始实验；截断回答仍是不完整结果，不能当作成功节省。实验运行期间不要修改供应商配置。

冷启动召回可能超过已配置的 `chatMemory.timeoutMs`。运行前检查该设置与 Server 就绪状态，各策略和后续复用批次保持相同召回设置。Source 同步、后台处理、成功召回是三个不同的检查点。处理稳定后检查累计记忆账本：准备统计已包含在累计统计中，额外后台处理的开销也不能从成本对照中省略。

## 限制与生命周期

每个宿主同时只运行一个实验。每批问题的截止时间为 15 分钟，准备阶段最多 4 分钟，每次回答最多 2 分钟、输出预算 1,024 Token。记忆召回使用已配置的超时、字节及条数限制。截断、失败、取消的回答均标为不完整，即使用量已经部分报告。停止会取消当前请求并阻止后续组继续运行，但不能撤销模型费用或已接收的 Source 处理。不会自动重试。

结果与人工检查标签只在当前宿主或浏览器会话保留：刷新浏览器会丢失人工标签，重启宿主或再次运行会覆盖上一结果。导出包含原始背景和回答，请作为私有内容保管。独立记忆范围仍保存在所配置的 Server 中，面板显示范围 ID，供通过 Server 支持的管理工具检查或清理。实验不会删除现有范围，不发送机器人指令，也不改变日常聊天的记忆策略。

单个合成场景是演示，不是通用基准。在宣传节省之前，应覆盖长短历史、重复运行，以及资料中没有答案的问题。
